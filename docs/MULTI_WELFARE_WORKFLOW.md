# 복지관 프로젝트 공통 작업 안내

이 저장소는 두 부분으로 나뉩니다.

- `outputs/`: 복지관 홈페이지 편집기와 실제 화면 자산
- `delivery-site/`: 로그인, 게시판, D1 데이터, R2 미디어를 담당하는 배포 앱

`skill-build/`, `node_modules/`, `__pycache__/`, 실제 `.env`와 `.dev.vars`는 자동 생성물 또는 비밀정보이므로 공유하지 않습니다. 다른 개발자는 원본 코드와 잠금 파일로 필요한 항목을 다시 만들 수 있습니다.

## 새 복지관 시작 순서

1. `config/institutions/institution.example.json`을 복사해 기관 영문 ID로 저장합니다.
2. 기관명, 주소, 연락처, 색상과 공개 링크를 기획자가 채웁니다.
3. 사진·로고 사용 허가와 개인정보 처리 기준을 담당자에게 확인합니다.
4. 개발자는 `outputs/`의 편집기 자산을 재사용하고 기관별 콘텐츠만 교체합니다.
5. `delivery-site/.dev.vars.example`을 `.dev.vars`로 복사하고 로컬 전용 비밀값을 설정합니다.
6. PC와 모바일에서 편집 → 저장 → 게시 → 공개 화면 흐름을 검증합니다.

기관 설정 예제는 협업 인수인계용 기준 문서입니다. 현재 편집기 데이터가 모두 설정 파일에서 자동 생성되는 구조는 아니므로, 설정 변경 뒤 실제 화면도 함께 확인해야 합니다.

## 역할별 온보딩

### 기획자

- 기관 설정 파일의 `contentOwner`와 공개 연락처를 확인합니다.
- 메뉴, 프로그램, 공지, 신청서와 개인정보 보유 기간을 확정합니다.
- 데스크톱·모바일 미리보기에서 문구 잘림과 이미지 속 인물 가림을 확인합니다.
- 담당자 승인 전에는 `status`를 `draft`로 유지합니다.

### 개발자

```powershell
git clone <저장소 주소>
cd <저장소 폴더>\delivery-site
Copy-Item .dev.vars.example .dev.vars
pnpm install
pnpm dev
```

Node.js 22.13 이상과 pnpm 11.9를 사용합니다. 변경 전후에 다음을 실행합니다.

```powershell
pnpm exec tsc --noEmit
pnpm test
pnpm build
```

편집기 전체 검증은 저장소 루트에서 `node tools/test-all.mjs`를 실행합니다.

### 검토자

- 공개 화면에는 편집 도구와 비공개 데이터가 보이지 않는지 확인합니다.
- 담당자 계정에서 수정·저장·재접속 후 내용이 유지되는지 확인합니다.
- 주민 게시물 승인, 반려, 신고, 수정·삭제 흐름을 확인합니다.
- 실제 배포 전 D1 백업 및 R2 보존 정책을 확인합니다.

## 브랜치와 변경 규칙

- 기관별 작업은 `codex/<기관-id>-<작업>` 브랜치에서 진행합니다.
- `git add .`보다 변경 파일을 경로별로 선별합니다.
- 공통 기능 변경과 기관 콘텐츠 변경은 가능하면 별도 커밋으로 나눕니다.
- `main` 반영 전 테스트 결과와 PC·모바일 화면을 함께 검토합니다.
- 기관별 비밀값이나 실제 게시판 데이터는 GitHub 이슈·커밋에 붙이지 않습니다.

## 환경변수와 저장소

| 이름 | 용도 | Git 커밋 |
|---|---|---|
| `TEMP_EDITOR_ID` | 임시 담당자 로그인 아이디 | 금지 |
| `TEMP_EDITOR_PASSWORD` | 임시 담당자 로그인 비밀번호 | 금지 |
| `BOARD_SESSION_SECRET` | 로그인 세션 서명(32자 이상) | 금지 |
| `BOARD_HASH_PEPPER` | 작성자 식별값 보호 | 금지 |
| D1 `DB` | 게시글·감사 기록 영구 저장 | 바인딩 이름만 허용 |
| R2 `MEDIA` | 이미지·영상 영구 저장 | 바인딩 이름만 허용 |

예제 파일에는 가짜 값만 둡니다. 운영 비밀값은 배포 서비스의 Secret 기능으로 등록합니다. 담당자 비밀번호를 소스 코드나 기관 설정 JSON에 넣지 않습니다.

## 데이터와 저작권 주의사항

- 루트 `data/`는 로컬 게시판·신청 데이터가 포함될 수 있어 커밋하지 않습니다.
- 주민 이름, 연락처, 신청 내용과 관리자 내부 메모를 샘플 데이터로 쓰지 않습니다.
- 사진, 로고, 폰트는 복지관의 공개 및 재배포 허가 범위를 기록합니다.
- 테스트 계정은 운영 계정과 분리하고, 전달 후 임시 비밀번호를 변경합니다.
- 백업 JSON은 담당자에게 안전한 경로로 전달하고 공개 저장소에 올리지 않습니다.

## 프로젝트 인수인계 체크리스트

- [ ] 기관 설정 파일 작성 및 담당자 확인
- [ ] 로고·사진·폰트 사용 권한 확인
- [ ] 관리자 비밀값을 배포 환경에 등록
- [ ] D1 `DB`, R2 `MEDIA` 연결 및 상태 확인
- [ ] 담당자 로그인과 수정·저장·게시 경험 확인
- [ ] 공개 방문자 화면에서 관리자 기능 비노출 확인
- [ ] PC·모바일 검수와 자동 테스트 통과
- [ ] 개인정보 정책, 백업, 장애 대응 담당자 기록
